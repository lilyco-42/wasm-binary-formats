APK 解包与网页资源运行

上传 .apk / .zip，在浏览器里列出条目；assets/ 下的网页资源可以直接在沙箱里跑起来。.exe / .dll 走 PE 头解析，只读不运行。其余常见二进制（tar / ar / deb / cab、gz / xz / bz2 / lz4 / zst、RIFF 与 TIFF、Matroska / WebM / MP4 家族、FLAC / MP2 / MP3 / Ogg / WAVE、MPEG-TS 节目表、PDF 页树、WebAssembly 模块段表、字体（含 WOFF2 表目录；TrueType 与 CFF 轮廓的 OpenType 分别定名，认的是目录里真列出的轮廓表，不是文件开头那四个字节自称的那个 flavour）、图标目录、Apple 二进制属性列表（对象表与引用图）、QOI 像素块流、JPEG 2000 盒子与 ihdr 字段、NumPy 数组头、HDF5 超级块与内部指针、Avro 容器块链、Arrow IPC 消息封包与文件块索引、Parquet 页脚与行组索引、ONNX 模型的计算图与张量元数据、HEIF 编码尺寸与可见尺寸、复合文件（CFB/OLE）的扇区别名表与目录条目、二进制 STL 的三角形计数与法线自检（它没有 magic，只有长度自己说话）、ICC 色彩配置的长度自证与标签表、增强图元文件（EMF）的记录链、设备单位与毫米两种单位下的画幅、PostScript 的 %% 注释与页数自证（声明与实际各说各话）、COFF 目标文件的节表、符号表与重定位记录（clang 在链接器之前留下的东西，长名字在串表里，字段与类型名逐个与 objdump 对过）、X.509 证书的 DER 对象树（顶层长度自己交代算不算整份文件，每个对象的偏移与长度、类型名与 OID 名都照 openssl 的 asn1parse 逐条核过；EC 公钥长度不写，因为那是曲线名里的事，不是字节里的事）、7z 容器的信封（头块位置从 32 字节起始头之后起算，归档自己声明的两个 CRC 逐字节复算；头块是明文属性树还是压缩流，决定这次能说到哪一步——文件名单子在流后面，没有对应解码器就不编造名字）、Photoshop 文档的头字段与 8BIM 资源表（这种文件从不声明总长度，所以真正自证的是图像数据那段：行程字节数之和要等于后面的负载，未压缩时由通道数 × 高 × 宽 × 位深/8 推算；图层记录只报跨度不解析——写这份样本的库自己把图层段声明成长度 0，照它写就会把读者绑死在一家实现上）、docx / xlsx / pptx / dotx / odt / epub 包（模板和文档的 part 名单一模一样，分别靠 manifest 里给主文档 part 声明的 content type —— 认的是文件自己写的那一行，不是扩展名）、vCard 名片（数的是折行还原之后的属性行：十四行物理文本里四行是上一行的续行，所以名片上有几个字段要跟折叠一起算才算得对；值只数不解析——反斜杠转义照原样留着，被转义的分号不算分隔符）会走结构解析，把头部字段、成员表与页树逐行列出来——读结构，不解码像素、不渲染文档、不执行任何代码。文件不上传，解包与解析都在 WebAssembly 内完成。

    按需加载的分析模块

    结构解析随 apk-lens.wasm 一起到位；反汇编、反编译这类分析引擎不在里面 —— 它们只在点下面这一行时才下载，没点就不占流量、不占内存，页面里也不存在实例。

      隔离方式：sandbox="allow-scripts" 且不给 allow-same-origin，因此被解出来的页面拿到的是独立的不透明源，读不到本站的 cookie、localStorage 或同源文档。相对引用一律改写成 data: URL —— blob: 在 Chromium 里会被存储键规则挡住，隔离中的页面取不到宿主生成的 blob。勾选"允许运行脚本"关闭时，脚本一并禁用。Chrome 还会额外执行帧内 CSP，把 fetch/XHR、嵌套 frame 与 worker 禁掉；不支持 csp 属性的浏览器只剩 sandbox 这一层，脚本仍可自行发起网络请求。
