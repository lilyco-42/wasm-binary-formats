APK 解包与网页资源运行

上传 .apk / .zip，在浏览器里列出条目；assets/ 下的网页资源可以直接在沙箱里跑起来。.exe / .dll 走 PE 头解析，只读不运行。其余常见二进制（tar / ar / deb / cab、gz / xz / bz2 / lz4 / zst、RIFF 与 TIFF、Matroska / WebM / MP4 家族、FLAC / MP2 / MP3 / Ogg / WAVE、MPEG-TS 节目表、PDF 页树、WebAssembly 模块段表、字体（含 WOFF2 表目录；TrueType 与 CFF 轮廓的 OpenType 分别定名，认的是目录里真列出的轮廓表，不是文件开头那四个字节自称的那个 flavour）、图标目录、Apple 二进制属性列表（对象表与引用图）、QOI 像素块流、JPEG 2000 盒子与 ihdr 字段、NumPy 数组头、HDF5 超级块与内部指针、Avro 容器块链、Arrow IPC 消息封包与文件块索引、Parquet 页脚与行组索引、ONNX 模型的计算图与张量元数据、HEIF 编码尺寸与可见尺寸、复合文件（CFB/OLE）的扇区别名表与目录条目、二进制 STL 的三角形计数与法线自检（它没有 magic，只有长度自己说话）、ICC 色彩配置的长度自证与标签表、增强图元文件（EMF）的记录链、设备单位与毫米两种单位下的画幅、PostScript 的 %% 注释与页数自证（声明与实际各说各话）、COFF 目标文件的节表、符号表与重定位记录（clang 在链接器之前留下的东西，长名字在串表里，字段与类型名逐个与 objdump 对过）、X.509 证书的 DER 对象树（顶层长度自己交代算不算整份文件，每个对象的偏移与长度、类型名与 OID 名都照 openssl 的 asn1parse 逐条核过；EC 公钥长度不写，因为那是曲线名里的事，不是字节里的事）、7z 容器的信封（头块位置从 32 字节起始头之后起算，归档自己声明的两个 CRC 逐字节复算；头块是明文属性树还是压缩流，决定这次能说到哪一步——文件名单子在流后面，没有对应解码器就不编造名字）、Photoshop 文档的头字段与 8BIM 资源表（这种文件从不声明总长度，所以真正自证的是图像数据那段：行程字节数之和要等于后面的负载，未压缩时由通道数 × 高 × 宽 × 位深/8 推算；图层记录只报跨度不解析——写这份样本的库自己把图层段声明成长度 0，照它写就会把读者绑死在一家实现上）、docx / xlsx / pptx / dotx / odt / epub 包（模板和文档的 part 名单一模一样，分别靠 manifest 里给主文档 part 声明的 content type —— 认的是文件自己写的那一行，不是扩展名）、vCard 名片（数的是折行还原之后的属性行：十四行物理文本里四行是上一行的续行，所以名片上有几个字段要跟折叠一起算才算得对；值只数不解析——反斜杠转义照原样留着，被转义的分号不算分隔符）、.torrent 的 bencode 树（每个字符串和整数自己报长度，所以要么这些长度刚好铺满整个文件、要么这文件不是它自称的那个东西；字典键的排序按 BEP-3 报告而不强求，pieces 是 20 字节哈希的平铺，长度能不能整除 20 也照实写）、OpenPGP 的包流（每个包自己声明负载长度，所以这条长度链要么刚好铺到文件末尾，要么它不是 OpenPGP；old 与 new 两种包头数长度 octet 的办法不一样，包行里就写明这一个用的是哪种；压缩包和加密包的正文已经不是包结构，读到那里就写 descend no 并停下，不假装看穿了流）、MSF 7.00 的程序数据库（.pdb：页大小与块数读自超级块，流表在它指的那几页里，每条流的大小和块清单照文件自己写的列；四条按位置定名的流（pdb / tpi / dbi / ipi）在不在，看目录里有没有字节 —— 类型记录在 TPI 流里面，那是按需加载的分析模块的事）、带注释的 JSON（.jsonc：注释与收尾的逗号就是它区别于普通 JSON 的全部，所以正文必须整体解析通过、而且至少留下其中一样，否则这份文件仍是 JSON 而不是它；成员树按文件自己的顺序列，容器在前、下属在后，路径、深度与标量的写法逐条与那个解析器的树核过，没解析完的注释不猜）、GPX 轨迹日志（.gpx：根元素叫 gpx、并且写明自己的 version，这就是它区别于其它 XML 文档的全部；要素树按文件列出的顺序排，经纬度照文件自己的写法报出来而不是过一遍浮点再打印（写成 47.60 的就还是 47.60），四个极值归第一次到达它的那个点，& 一类预定义实体解码，&deg; 这种要外部定义才认得的、CDATA、DOCTYPE 一律整份拒绝而不是半猜；一个点都没有的日志不报空边界）、3MF 模型包（.3mf：和 OOXML 同一套 zip + XML 的包壳，但认的不是部件名的前缀，而是 _rels/.rels 里那条类型指向 …/3dmodel 的关系 —— 目标前面带不带那个斜杠都指向同一个部件，指到压缩包里并不存在的部件就整包拒绝，并写明跟的是哪条指针。模型部件本身是要读的：单位照文件写的报，没写就写未写，不替它套规范默认的毫米；每个对象的顶点与三角形数取自它自己那棵子树，总数与 ElementTree 在同样的字节上数出来的那两个数一致；超过遍历上限的模型整份拒绝，不列半份）、XML Schema 定义（.xsd：根元素叫 schema，并且在它自己身上把 …/2001/XMLSchema 这个命名空间绑给它自己——整份文件对“我是什么”只说了这一句，所以认的就是这句绑定：不是前缀写成 xs 还是 q，也不是扩展名，而“值里出现了这个 URI”也不算，得是元素自己那个前缀所绑定的那一条；全局声明按文件列出的顺序一行一条，类型与属性的引用照文件自己的写法报出来（tns:Item 就写 tns:Item），要不要把它解开成真正的类型是编译器的事——那要全文的前缀表加上 import 指向的那些文件，这一层不读；XSD 1.0 和 1.1 共用同一个 URI，所以这里不报版本；“认得出”和“编译得过”也分开写：四份样本在 xmlschema 和 JDK 自带的 Xerces 两处都干净通过，第五份 broken.xsd 两处都拒绝、这一页照样把它的两条声明列出来，因为引用了没声明的类型是一份写错的 schema，不是一份不是 schema）会走结构解析，把头部字段、成员表与页树逐行列出来——读结构，不解码像素、不渲染文档、不执行任何代码。文件不上传，解包与解析都在 WebAssembly 内完成。

    预览 / 运行

    选中左侧一个条目。HTML 条目会在隔离 iframe 中运行。

    按需加载的分析模块

    结构解析随 apk-lens.wasm 一起到位；反汇编、反编译这类分析引擎不在里面 —— 它们只在点下面这一行时才下载，没点就不占流量、不占内存，页面里也不存在实例。

      隔离方式：sandbox="allow-scripts" 且不给 allow-same-origin，因此被解出来的页面拿到的是独立的不透明源，读不到本站的 cookie、localStorage 或同源文档。相对引用一律改写成 data: URL —— blob: 在 Chromium 里会被存储键规则挡住，隔离中的页面取不到宿主生成的 blob。勾选"允许运行脚本"关闭时，脚本一并禁用。Chrome 还会额外执行帧内 CSP，把 fetch/XHR、嵌套 frame 与 worker 禁掉；不支持 csp 属性的浏览器只剩 sandbox 这一层，脚本仍可自行发起网络请求。
